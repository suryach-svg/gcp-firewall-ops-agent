# Rubric evidence map (AgentOps Code Review Matrix, 95 points)

Where each criterion is implemented, with the exact files and symbols to read.

## 1. Tool & Interface Design

| Criterion | Evidence |
| --- | --- |
| **Comprehensive tool docstrings** | Every tool has a Google-style docstring with purpose, when to use it, `Args:` and `Returns:` (including error shapes): `firewall_ops_agent/tools/inventory_tools.py` (`list_firewall_rules_for_scope`, `get_firewall_rule_details`), `tools/analysis_tools.py` (`analyze_firewall_rule_risks`, `explain_firewall_risk_check`), `tools/knowledge_tools.py` (`search_firewall_best_practices`), `tools/remediation_tools.py` (`propose_least_privilege_rule`, `apply_firewall_remediation`). ADK turns these into the function declarations the model sees. |
| **Descriptive naming** | Verb + object + qualifier names that state exactly what happens: `list_firewall_rules_for_scope`, `analyze_firewall_rule_risks`, `get_firewall_rule_details`, `explain_firewall_risk_check`, `search_firewall_best_practices`, `propose_least_privilege_rule`, `apply_firewall_remediation`. Agents are named by role: `rule_collector_agent`, `risk_analyst_agent`, `report_writer_agent`, `report_grounding_verifier`, `firewall_ops_coach`. |
| **Explicit JSON schemas** | Pydantic models in `firewall_ops_agent/schemas.py`: `ScopeRequest` (validated scope IDs, cross-field rules), `FirewallRule`, `RiskFinding`, `RiskReport`, `RemediationProposal`, `ToolError`; `RemediationRequest` in `tools/remediation_tools.py` rejects internet-wide CIDRs. Tool parameters are `Annotated[..., Field(...)]` with `Literal` enums (`scope_type`, `change_type`, `min_severity`), regex `pattern`s (scope and check IDs), numeric bounds (`max_findings` 1-50) and per-parameter descriptions; ADK emits all of them in the function declaration the model sees (`tests/test_tools.py:test_tool_declarations_carry_enums_patterns_bounds_and_descriptions`). |
| **Guided error handling** | Tools never raise to the model; they return `ToolError` (`status`, `error_type`, `message`, `recovery_hint`) via `tools/_common.py:tool_error`. Cloud exceptions are translated with role-specific fixes in `tools/_common.py:map_exception_to_error` (tested with real `google.api_core` exceptions); partial reads (an unreadable network or policy parent) return `warnings` instead of failing; unknown rule names get close-match suggestions and names present in several audited scopes return `ambiguous_rule_name` with a `scope_id` hint (`tools/_common.py:resolve_rule`); missing architecture facts return `status="needs_input"` with the exact question to ask (`propose_least_privilege_rule`). `guardrails/policy_plugin.py:GuidedToolErrorReflectionPlugin` (ADK `ReflectAndRetryToolPlugin`) feeds the `recovery_hint` back as reflection guidance with bounded retries. |

## 2. Context & Memory

| Criterion | Evidence |
| --- | --- |
| **Robust system instructions** | `firewall_ops_agent/prompts.py`: a shared `SAFETY_CONSTITUTION` (grounding, no re-rating, never widen access, approval required, no secret disclosure) plus a `FIREWALL_DOMAIN_PRIMER`, and per-agent instructions defining persona, procedure and output format. A test asserts every LLM agent carries the constitution (`tests/test_memory_and_wiring.py`). |
| **History compaction** | `agent.py:build_app` configures ADK `EventsCompactionConfig` with both triggers: sliding window (`compaction_interval`, `overlap_size`) and token threshold (`token_threshold`, `event_retention_size`), summarized by a cheap model via `LlmEventSummarizer`. Also `ContextCacheConfig` (context caching), compact tool outputs with full data kept in session state (`tools/_common.py:compact_rule`, `MAX_RULES_IN_TOOL_RESPONSE`), and `include_contents="none"` for the report writer (`sub_agents/audit_pipeline.py`). |
| **Persistent session state** | `memory/services.py:build_session_service`: ADK `DatabaseSessionService` (SQLite locally, Cloud SQL/PostgreSQL via `SESSION_DB_URL`) or `VertexAiSessionService` on Agent Runtime (regional `AGENT_ENGINE_LOCATION`). Each audited scope has its own state key (`firewall_inventory/<scope>`, `risk_report/<scope>`, see `tools/_common.py`), so state deltas stay small and lookups never mix scopes. Long-term memory: `VertexAiMemoryBankService` or ADK `SqliteMemoryService`, retrieved by the coach with `load_memory`. Retrieval over the knowledge base uses a TF-IDF vector index (`core/knowledge_base.py`). Persistence across restarts is tested in `tests/test_end_to_end_offline.py:test_state_persists_across_restart`. |
| **Async memory operations** | `memory/services.py:BackgroundMemoryIngestionPlugin` schedules memory generation with `asyncio.create_task` in `after_run_callback`, sending only the current turn (`add_events_to_memory`) and never blocking the response. DLP calls run in `asyncio.to_thread`, and so do the blocking Compute Engine calls inside the `async` tools (`tools/_common.py:load_rules`, `tools/remediation_tools.py`). Non-blocking behaviour is tested in `tests/test_memory_and_wiring.py:test_background_ingestion_does_not_block_the_response`. |

## 3. Orchestration & Logic

| Criterion | Evidence |
| --- | --- |
| **Multi-agent patterns** | Coordinator/dispatcher: `agent.py:build_root_agent` (`firewall_ops_coordinator` with LLM-driven `transfer_to_agent`). Sequential pipeline: `sub_agents/audit_pipeline.py` (`SequentialAgent` with `output_key` hand-off: `collection_summary` -> `risk_analysis` -> `final_report`). Custom deterministic agent: `sub_agents/grounding_verifier.py:ReportGroundingVerifier` (`BaseAgent`). Specialist: `sub_agents/ops_coach.py`. |
| **Strategic model routing** | `config.py:Settings.model_routing_table` maps each `TaskProfile` to fast / reasoning / lite models; `config.py:resilient_model` uses ADK `FallbackModel` (reasoning model fails over to fast on 429/5xx); two per-request callbacks in `routing.py` upgrade the fast model to the reasoning model: `escalate_for_complex_questions` (coach: complex intent, long request or large inventory) and `escalate_for_large_inventories` (report writer: inventory size only), logged as `model_routed`. |
| **Guardrails & policy plugins** | `guardrails/policy_plugin.py:SecurityGuardrailsPlugin` (user-input redaction in `on_user_message_callback`, input guardrail before any model call, tool-call budget, scope allowlist, ban on exposure-widening CIDRs, secret scrubbing of model output); `guardrails/input_guardrails.py` (narrow patterns, tested against attack phrasings *and* everyday firewall questions); self-evaluation by `sub_agents/grounding_verifier.py` + `core/grounding.py` (unknown rule names, uncovered high risks, posture-score drift); reflect-and-retry plugin. |
| **Human-in-the-loop hooks** | `tools/remediation_tools.py:apply_firewall_remediation` calls `tool_context.request_confirmation(...)` and returns without changing anything until a human approves; rejection is honored and audited; live changes also require a change ticket in the approval payload (`rejected_missing_ticket` otherwise). The terminal client handles approvals in `scripts/chat_cli.py`. Approve and reject paths are tested end-to-end. |

## 4. Observability & Tracing

| Criterion | Evidence |
| --- | --- |
| **Structured JSON logging** | `observability/logging_config.py:JsonFormatter` emits one JSON object per line with `severity`, event fields and Cloud Logging trace correlation (`logging.googleapis.com/trace`, `spanId`). |
| **Intent vs. outcome capture** | `observability/agentops_plugin.py:AgentOpsObservabilityPlugin` logs `model_intent` -> `model_outcome`, `agent_decision` (tools the model decided to call, with redacted args), and `tool_intent` -> `tool_outcome` (status, duration, summary), mirrored as OpenTelemetry span events. |
| **Distributed tracing** | `observability/tracing.py`: wires ADK's OpenTelemetry spans to Cloud Trace (`get_gcp_exporters`) or the console; `traced_operation` adds child spans around Compute API reads, risk analysis, knowledge-base search and firewall patches. `adk deploy agent_engine --otel_to_cloud` enables it on Agent Runtime. `apply_privacy_defaults` keeps raw prompts and responses out of spans unless an operator opts in (`ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS`). |
| **PII redaction** | `observability/redaction.py` (secrets, tokens, keys, emails, phones, SSNs, Luhn-valid cards, public host IPs; optional Cloud DLP `deidentify_content`). Applied to user messages before they are stored or sent to a model (`redact_user_input` via `SecurityGuardrailsPlugin.on_user_message_callback`; keeps IPs/CIDRs the agent needs), by the JSON log formatter and the AgentOps plugin, to span attributes, and to every event before it reaches long-term memory (`memory/services.py:redact_event`, `RedactingMemoryService`), even when the host injects its own Memory Bank. Tested end-to-end in `tests/test_end_to_end_offline.py:test_user_input_is_redacted_before_session_storage_and_model_calls`. |

| Criterion | Evidence |
| --- | --- |
| **Automated evaluation suites** | Golden dataset regression (`eval/golden/golden_findings.json`, `eval/run_golden_eval.py`, CI fails on any regression); ADK eval set and criteria (`eval/agent_evalsets/*.json`) run through `AgentEvaluator` offline in CI and live with `RUN_LIVE_EVAL=1` (`tests/test_agent_evaluation.py`); 136 offline tests plus 1 opt-in live test in `tests/`, including the live data source against real `compute_v1` messages with fake clients (`tests/test_live_data_source.py`). |
| **Infrastructure as code** | `infra/terraform/` (APIs, least-privilege service account, project/org/folder IAM, optional custom remediation role limited to patching existing VPC rules, Secret Manager secret, log-based guardrail metric), validated with `terraform validate` in CI. Agents CLI: `agents-cli-manifest.yaml` (from `agents-cli scaffold enhance --from-adk-project`) plus documented `agents-cli info / playground / run / lint / eval run / deploy` commands and Makefile targets (README "Use the Agents CLI"); ADK deployment via `adk deploy agent_engine` (`Makefile:deploy`). |
| **Secure secret management** | No keys in code: ADC/service account on Google Cloud; optional developer key loaded from Secret Manager at startup (`config.py:configure_model_credentials`, `load_secret`); `.env` git-ignored; keyless Workload Identity Federation in CI (`.github/workflows/ci.yml`); repository secret scan in `tests/test_memory_and_wiring.py:test_repository_contains_no_hardcoded_secrets`. |
